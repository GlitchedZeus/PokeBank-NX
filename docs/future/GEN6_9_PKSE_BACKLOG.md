# Gen VI–IX: PKSE October 2026 features and repairs to implement later

**Status: reference only, no runtime code.** Owner Oct 28: keep every newer-generation change from the PKSE
October window for the Gen VI–IX phase, which starts after Gen I–V is complete and merged. Sources: PKSE
`version-1.2.2` `a79fe61a` (and v1.2.1 `94ffce58`). The pinned PKHeX checkout is sparse and lacks the Gen 6+
files, so every PKHeX comparison below is **not confirmed** unless a file:line is given; confirm each against
PKHeX before implementing.

Rules for that phase (owner): no Hyper Training fields on Gen I–V formats; no automatic-illegal-values bypass;
Alpha changes validate the dependent size fields, never flip the bit alone; every change ships with native
round-trip, checksum and byte-diff tests; nothing touches the legality engine (PR #314) until separately
authorised.

Already fixed early (reachable today through the Bank true Move): **B-LA-1** catch-count inflation (C-1) and
**B-LGPE-1** zeroed blank slots (C-2), on `integration/gen15-combined`. Their wider upstream scope (alpha and
size research tasks, update counters, nobles) remains below.

## Backlog (October window)

Each item needs its Gen VI+ format support switched on first. Where noted, PokeBank NX already carries the pre-fix
PKSE code in its legacy classes, and that code is reachable through Switch backup-workspace saves
(`Save::buildWorkspaceImage`, `src/Save/GetSaveFileContents.cpp:218-319`: GG/SWSH/ZA/SV/PLA branches call
`update*Block` including `updatePokedexBlock`; BDSP is refused at `:309`).
