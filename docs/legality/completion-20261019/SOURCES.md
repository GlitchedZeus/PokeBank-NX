# Evidence, attribution and limits

The machine source hashes and immutable URLs are in SOURCE_PINS.json and RULE_INVENTORY.json. These are evidence references, not proof of an individual's historical distribution or receipt.

- PKHeX baseline: `kwsch/PKHeX@6501f0ab46e8f8ca048539dbaf8cae8cb104e722`. Current comparison: `6042efa241a9925ce57e645329ea7f976deabdd3`. The legality-source scan found 828 baseline and 837 current check-result occurrences and 102 changed files. Applicability and multi-line helper dispatch still require semantic review; these numbers are not rule counts.
- Korean save offsets: `PKHeX.Core/Saves/Substructures/Gen12/SAV2Offsets.cs`, `LoadOffsetsKorean`; layout, box-name length and pockets. `SAV2.cs` supplies native decoding and checksum behavior. The parser validates the main checksum and existing structural invariants; it does not newly authenticate the Korean secondary mirrored checksum scheme.
- Korean charset: `PKHeX.Core/PKM/Strings/StringConverter2KOR.cs`, `LoadString`, `Table0` through `TableB`. Generated mapping data is GPL-3.0-or-later, attributed in its generated header; the full upstream license is in ../../third_party/PKHeX-GPL-3.0.md. GPLv3 section 13 permits the combination with this AGPLv3 project. Regeneration is pinned and byte-reproducible. No ROM or graphical assets were imported.
- The differential search keeps its separately generated oracle charset; production uses Gen2ReadOnlySave's decoder and explicit per-record encoding. Korean names imported into Western saves are not silently assigned the container's encoding. The native save parser tests are synthetic structural specimens; no authenticated Korean personal save was supplied.
- Korean link behavior lead: `Greatpriceman/pokegold-ko@3cca49e5a0e306ea340015a25fc97b6fc07938f9`, especially `korean_function_export/Serial,asm`. Its README explicitly says it does not yet rebuild the ROM. This is a research lead, not independently authenticated game behavior. Korean–Western/ Japanese/Time Capsule compatibility is therefore not newly certified by this session.
- Gen III berry locations/sizes: baseline PKHeX `Saves/Blocks/Gen3/SaveBlock3LargeRS.cs`, `SaveBlock3LargeE.cs`, `SaveBlock3LargeFRLG.cs`; `SAV3.EBerryName`, `IsEBerryEngima`; name/language policy in `Saves/Substructures/Gen3/EReaderBerrySettings.cs`; item policy in `Legality/Verifiers/ItemVerifier.cs`.
- Original native berry validity: `pret/pokeruby@5784633ce4ef7ade1a7f2d2d0c288e3d5e6cdd7f`, `src/berry.c`, `GetEnigmaBerryChecksum`, `IsEnigmaBerryValid`: omit the two runtime pointers when summing; require nonzero stageDuration/maxYield. Emerald and FireRed use the compact berry and sum preceding bytes directly; their exact pins are in SOURCE_PINS.json. The C++ implementation reads copies only and does not temporarily zero pointers in source saves.
- Save evidence is local to a validated source, exact assigned title, active sector copy and supplied save-language. A Pokemon's language is never substituted for the save language. Missing/bad context stays Unknown. A recognized name plus native structure/checksum is the implemented item policy; it is **not authentication of an entire historical e-Reader payload**, date, owner, distribution ROM or event receipt.

# Existing historical work preserved, not re-certified

GEN1_5_RULE_COVERAGE.md, GB_LEGALITY_VERDICTS.md, GEN3/4/5_PKHEX_RULE_INVENTORY.md and PKHEX_DISAGREEMENT_REVIEW.md retain prior references and rationale. GEN1_RBY_GIFTS_EVENTS_NATIVE_HANDOFF_20261012.md distinguishes native NPC/gift mechanics from authentic distribution evidence. No existing Mew, Celebi, GameCube, Ranch, PCD/PGT or PGF implementation was removed.

This session did not locate authenticated original Mew distribution media, individual event receipts, a complete Japanese Mobile System distribution archive, a complete e-Reader shadow archive, or an exhaustive PGF preservation set. PKHeX's templates are not independent authentication. Existing Japanese GS Ball Celebi behavior remains covered by the GB corpus; other unrecorded distributions retain Unknown. Retail glitch routes are not silently added to ordinary acquisition policy.

Claims that these categories are complete, or that this session independently proves the prior stricter Gen IV met-location rule, would be unsupported. Every raw disagreement remains in the metrics and mismatch index; independent review and actual cartridge/hardware acceptance remain outstanding.
