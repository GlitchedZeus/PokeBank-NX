## Current implementation and wiring

`Gen4LeadFrameEvidence::reversalWindow` and `Gen4WildRngCorrelation::reversalWindow` stop after 128 previous PID pairs and return -1. The ordinary matcher returns no match when that happens. Existing accepted native BCC tests cover one/two nature rejections and deeper minimum-31 rerolls; these are different loops. This is **Implemented but incomplete**, not a missing Method K implementation.

No encounter seed is fabricated or represented as a capture proof.

## Algorithm / seed reconstruction / pseudocode

HGSS no-lead nature is upper16(next(state)) modulo 25. Generate PID as low16 output then high16 output; reject while PID modulo 25 differs from target nature. Retail has no 128 cap on this loop. After accepting PID, the reference generates IVs from subsequent outputs. Reverse from a recovered pre-PID seed by pairs until the first earlier PID matching that nature determines the boundary; the engine currently imposes 128 as a resource bound.

```
loop:
  low = next16(); high = next16()
  pid = low | high << 16
  if pid % 25 == nature: retain; break
```

Full Method K still requires exact slot, level, activation, lead ability, shiny/IV and special-encounter rules. Do not use this stage witness to assert that any chosen encounter table row is compatible.

## Inputs / lost evidence / proposed integration

Need native PID/IVs, original game, candidate slot/rate/level/species and trainer IDs for complete encounter reconstruction. Lead identity and rejected PIDs are not stored. Reuse existing seed recovery, then expose `Matched`, `NoMatchWithinSupportedModel`, and `SearchExhausted` separately. Keep explicit resource budgets; changing the cap to 256 merely changes the bound and cannot establish exhaustiveness.

## Tests, hard-Invalid boundary and acceptance

Positive: exact sequence above must be accepted by an extended forward/reverse stage checker. Negative: force an earlier rejected PID as the retained PID while keeping nature 20; reject that fixed history. Unknown: only the capped search ran, or slot/activation/lead information was not checked. No hard Invalid may follow from -1 alone.

Acceptance: keep existing BCC one/two-rejection native regressions green, add this long-history stage vector, prove exhaustion remains Incomplete, and then obtain a fully source-matched native PK4 fixture before claiming broader encounter coverage. Implement this after move-source infrastructure unless a consumer is found converting exhaustion to Invalid. No such false-Invalid consumer was demonstrated in this tranche.
