## HGSS forward algorithm

Use physical deposited slot 0/1, not named move-father/mother roles. Each random call advances `state = state * 0x41C64E6D + 0x6073 (mod 2^32)` and returns the high 16 bits.

| Power item count | Forced stat/donor | Other draws | Total draws |
|---|---|---|---:|
| None | None | 3 stat-index draws, then 3 donor draws | 6 |
| One | Item's target stat, item holder's physical slot | 2 stat-index draws, then 2 donor draws | 4 |
| Two | First draw selects one holder: odd → slot0; even → slot1 | 2 stat-index draws, then 2 donor draws | 5 |

Two identical Power items still consume the holder-selection draw. Two different Power items do not force both stats. Only one selected holder supplies the guaranteed stat.

Item mapping: Weight 294→HP, Bracer 289→Atk, Belt 290→Def, Anklet 293→Spe, Lens 291→SpA, Band 292→SpD. Zero is the harness's no-item control. Other non-Power items follow the non-Power branch; their own effects on other egg stages are outside this replay.

Initialize available stats `[HP,Atk,Def,Spe,SpA,SpD]`. Remove the forced stat if present. For each remaining inheritance position `i`, draw index modulo `6-i`, select that available stat, and remove that **selected list index**. Then draw physical donor slot modulo 2 for each non-forced position. Apply all three selected assignments. The three selected stats are distinct, but the child's final IV values can coincide with initial values or each other; do not infer selected stats just by counting changed values.

## Platinum forward algorithm

There is no Power-item lookup in `Egg_InheritIVs`. Draw three selection values modulo 6,5,4 and read from the current available-stat array. After each read, remove array **position i**, not the selected index. Compact non-sentinel values to the front without clearing the stale tail. Then draw three physical donor slots modulo 2 and apply the assignments in order. A repeated stat is overwritten by its later assignment.

This matches the Emerald-style removal behavior at this stage, but does not establish that the complete Emerald and Platinum egg-generation pipelines are interchangeable. In particular, pending PID generation and other RNG stages are excluded here.

## Reversal boundary

Given an independently known final stage state and the exact game/held-item branch, apply the inverse LCRNG step exactly 6 times for Platinum, and 6/4/5 for HGSS's zero/one/two Power-item branches. Inverse multiplier is `0xEEB9EB65`; use `previous = (state - 0x6073) * inverse (mod 2^32)`. Then replay and compare every supplied output.

This does not recover a unique stage state from stored child IVs. Unknown held items imply unknown draw count; enumerate explicitly bounded hypotheses or return Unknown. Unknown deposit order must not silently mean father first. Matching outputs establish compatibility with the supplied stage, not historical authenticity.

## Inputs, information loss and hard-Invalid boundary

PK4 stores the resulting child IVs/PID and origin fields, not parents' collection-time held items, deposit order, initial pre-inheritance IVs, or RNG state. Trades and hatching do not restore these facts. Source-game and stage witnesses require independent provenance. A fixed supplied construction may be contradicted; no failure of this helper alone establishes global Invalid across alternate parents, items, initial values, seeds or event origins.

Implementation order: pure stage replay → input-domain and availability checks → inverse for known boundaries → independent source fixtures → corrected parent-slot binding → joint moves/IV evidence. Full pending PID, Everstone/international stages, DP retail confirmation and native save-derived histories remain unresolved.
